# 公共接口与候选替换规则 v1
本文件与contracts/一起随三个个人包分发。每人只实现自己的模块，不等其他成员逐项签字才开工。
实现发现真实歧义时提交一个最小反例并一次修正规格；不能分别静默发明不同解释。
以下是本版新增的软件模块边界，不宣称旧B2内部KernelMeta已经按此冻结。

## 1. 计算后端 SP_LINEAR_V1
### 1.1 共同数学（沿用B0/B2已描述的数学）
逻辑X[T,K]、W[N,K]，Y=X·W^T。T=1..8，N/K=1..4864。
首版实际负载为24层的gate/up: N=3584,K=1024；down: N=1024,K=3584。
Kp=ceil(K/128)*128，Np=ceil(N/32)*32，G=Kp/128。
W4按输出行和128输入元素分组，Sw=absmax/7；A8按每条有效输入行，Sx=absmax/127。
全零组scale=1，码=0；padding不参与scale；NaN/Inf拒绝；舍入ties-to-even，最后夹到合法码。
W范围[-7,7]，-8拒绝；X范围[-127,127]，-128拒绝。Sw/Sx必须为有限正数。
每128输入用INT32部分和，随后按float32(float32(S)*Sw)*Sx恢复，每组依g递增顺序加到FP32累加值。
禁用会改变参考语义的fast-math/FMA重结合；整数部分必须逐位一致，浮点按下面门槛。
每组最大绝对INT32部分和113792，不把全K跨组整数累加后再乘单个scale。
Bias、SiLU、门控、残差、RMSNorm以及模型状态不在该API内处理，由运行时按原模型执行。

### 1.2 布局
所有二进制小端，长度为字节。权重文件与输入是主机普通地址，只有后端库能转换为XRT管理的BO。
W字节偏移：(((n//32 * G + k//128)*128 + k%128)*16)+(n%32)//2。
偶数输出lane低4位，奇数lane高4位，同一个k的两个输出行放一字节；不是相邻两个k。
Sw索引：(n//32*G+k//128)*32+n%32。
xq为[T,Kp] INT8，sx为[T] FP32，y为[T,Np] FP32。
W长度Np*Kp/2，sw长度Np*G*4，xq长度T*Kp，sx长度T*4，y长度T*Np*4。
padding权重及激活为0，padding权重scale为1，输出填充列成功时必须写0。
核内部meta不属于公共文件格式，由各自的库私有处理。交付报告必须写真实内部版本而不是伪装统一。

### 1.3 共同C ABI
见contracts/sp_linear_v1.h。使用不透明ctx与uint64权重句柄，无C++ STL对象跨库；不抛异常越过C边界。
- open：读本地配置，检查设备/平台/位流/数学契约，加载指定后端。
- load：一次性接收已量化权重和scale，返回权重句柄。成功返回前后端取得所需数据所有权；调用方可释放原临时数组。
- run：接收A8输入及scale，返回输出；同时只允许一个in-flight任务。
- report：输出上一次任务及能力/版本JSON；先查询required_bytes（含\0），不足返回BUFFER_TOO_SMALL，不输出半截JSON。
- unload/close：只能在已确认无硬件访问时释放；超时不意味着DMA已经停止。
本包头文件是声明和可编译的边界，不是现成的XRT实现。

### 1.4 生命周期和错误
重复加载/卸载、零句柄、错尺寸、短缓冲、保留码、非有限scale、错误job_id/位流全部有测试。
run失败时y视为不可用，无论是否看起来合理；禁止使用上次输出。
非零job_id由运行时生成，库须用硬件回显核对。实现未提供真实计数器时report填null，不由主机自增冒充。
超时把ctx置POISONED，禁止接受新任务、释放可能仍被DMA引用的BO或卸载动态库；先按已验证平台流程停止/恢复设备。
close无法安全停止时返回BUSY/POISONED并保持资源；应用停止接收新会话并展示故障，不能继续生成伪硬件结果。
切换A/B后端只在维护窗口停止服务后进行；设备状态不能由两套库同时拥有。

report至少包含：api_version、contract_sha256、backend_id、device_id、xclbin_sha256、kernel_build_id、job_id、execution_kind、status、hardware_done_count、weight_resident、quant_ms、input_sync_ms、kernel_ms、output_sync_ms、service_ms、algorithm_weight_bytes、measured_bus_bytes、cycles。
execution_kind使用CPU_REFERENCE或FPGA_REAL；无硬件测试环境不能填FPGA_REAL。未测量的字节/周期/能耗填null。
quant_ms由运行时另记；后端没做输入量化时report此项为null，汇总时不得漏掉运行时量化成本。

### 1.5 正确性门槛
整数部分bit-exact；输出逐元素abs_err≤1e-4+1e-5*abs(y_ref)，并报告NRMSE/最大绝对误差。
这是本版预设验收门槛，不是“硬件已达到”；量级导致失败时先排查浮点顺序，不在看完候选成绩后改标准。
同数学CPU与PL分别验证单层、全图teacher-forced logits和自然生成任务质量；长序列浮点差异不能只用最后一句相同证明正确。
独立参考不得调用待测HLS核或导出器生成期望值。

## 2. 语音服务 SP_VOICE_V1
### 2.1 进程边界
入口为持久本地进程，UTF-8 JSONL一行一条；stdout只放协议，诊断放stderr。
每条请求含api_version=1、request_id、op。响应必须回显id与op，type为result/error/event。
路径必须在主应用批准的spool目录内，不允许../、任意绝对路径、链接逃逸或shell拼接。
原始音频不上传网络，不把转录、病例和成绩用于外部服务。无公网时冷启动可运行。
A主应用负责麦克风输入与播放；C仅处理音频/文字，不读取Qwen、病例或评分文件。
各worker隔离依赖，不能要求主应用升级其Python或更换系统音频驱动才能接入。

### 2.2 必需操作
hello：返回module_id、模型/许可证版本、流式能力、支持采样率、并发上限、execution_kind。
transcribe：传入mono PCM16 WAV路径及language=zh，返回text、audio_duration_ms、compute_ms、confidence可为null。
synthesize：传入已经通过事实检查的完整短句及output_dir，返回wav_path、sample_rate、frames、compute_ms、text_sha256。
cancel：根据request_id取消；若内核不能中断，标cancel_pending并丢弃迟到结果，不伪称已经停止。
reset：清理指定会话的ASR状态和临时资源，返回新epoch；不得删病例或其他会话。
shutdown：等待/结束自有任务，关闭进程。
请求格式样例见contracts/voice_examples.jsonl，示例不是语音模型已运行的日志。

### 2.3 可选流式ASR（通过hello能力位启用）
asr_begin(session_id, sample_rate=16000, channels=1, format=pcm_s16le) → stream_id。
asr_push(stream_id, seq, pcm_path, final=false) → 可选partial事件；按seq单调处理，ack后才能删除输入文件。
asr_finish(stream_id) → 唯一final结果；seq错误、重复final或旧epoch结果必须拒绝。
每块建议200ms；块大小属配置，端点检测可调但冻结评测前确定。
非流式worker仍可运行：主应用调用transcribe，能力差异计入端到端比较而不是偷偷改变计时起点。
partial结果仅供显示，不进入计分/模型提示；final才提交。

### 2.4 TTS与时间边界
ASR输入在主应用统一16k mono PCM16；TTS可按模型原采样率返回，显式给出真实sample_rate，再由主应用受控重采样。
不以8k音源上采样宣称高音质，不任意提高语速降低等待。
首句音频ready不等于扬声器已经出声。主应用记录实际播放首个有效音节，worker只报告compute与ready。
测试集含中文否定、时间、数字、症状和术语；不得使用模型默认confidence伪装经校准置信度。

## 3. 包规范：A不必读一堆过程文件
计算包：manifest.json、源码、构建入口、shared library、匹配kernel.xclbin/平台加载材料、selftest、证据目录。
语音包：manifest.json、源码、worker入口、锁定依赖、模型来源/许可、安装和selftest、质量/速度报告；许可允许时才附权重。
发布manifest记录每个文件SHA256、契约摘要、工具/平台信息、各域测试状态、未通过项、复现命令。不能只有截图或一个README。
本包tools/verify_bundle.py只静态核验相对路径和哈希，不执行陌生脚本、不刷机、不判断性能达标。
normal流程：读取1页摘要→运行静态检查→运行已确认的自测→统一基准→写选择记录；只有失败时深入源码。
第一次10月14日发电脑候选；第二次10月22日发带实板证据的候选。A无需每天拉取。

## 4. 默认选择和替换
配置模板只描述将来目录，文件未安装时不能宣称启动成功。
linear_backend=A，voice_backend=A是默认。候选选择是维护窗口的一次更换，不是模型或后端频繁切换。
缺B包继续A计算；缺C包继续A语音；两者缺失都不阻塞默认系统验收。

## 5. 预先登记的采纳门槛（本版设计规则）
所有候选先满足相同质量、内存、稳定性、许可和真实性底线。
B：同W4A8、相同层范围和硬件条件，首选要求模型阶段/整轮p95耗时改善≥5%且配对置信区间支持改善；或每轮能耗改善≥10%且时延不退化超过3%。
若只有核内快、包含同步后不快，标“局部优化”，默认不替换整机。实测时报告含量化、输入输出和调用开销的负载加权结果。
C：首段有效语音p95改善≥10%，或关键识别项错误显著降低；普通CER、否定/数字/时间错误不恶化，盲听可懂度/音质无明显下降。
C靠提高语速、漏播否定、提前截断、忽略难样本或只用预缓存答复取得的改善无效。
质量非劣界限在开发集登记：例如CER绝对差≤1个百分点，关键项不增加错误；最终测试前冻结，不按结果改阈值。
至少30次重复性能运行、200轮端到端，固定样本与随机顺序；报告配对bootstrap区间、失败/超时及回退。不能只比较平均数或最好一次。
B/C单独通过后再组合验证，组合可能资源争用，不能假设两个收益直接相加。
