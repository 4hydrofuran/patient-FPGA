# A2 内存清单：规划而非板端预算

依据 `quant/evidence/source-graph-audit-20260928.json` 的真实shape统计。W4组128/tile32及FP32尺度仅用于用户指定方向的容量测算；契约未冻结，尚无sidecar文件。所有实测驻留、CMA/BO上限均null。

| 项目 | 已知文件/负载字节 | 驻留策略与风险 |
| --- | ---: | --- |
| 原始BF16 safetensors有效tensor | 988,065,536 | 仅离线导出/诊断使用，运行时不加载它与另一套完整模型 |
| 其中72个MLP BF16 | 627,572,736 | A3必须避免将这份MLP再完整载入，与sidecar重复常驻 |
| 原F16 GGUF整个文件 | 994,156,736 | 文件大小≠RSS；mmap本身不保证模型页不驻留，默认loader仍可能预取/加载全部MLP |
| 预计全部MLP W4 payload | 156,893,184 | 离线一次量化；不允许每token重新量化权重 |
| 预计全部MLP FP32尺度 | 9,805,824 | 和W4使用同一版本/hash；上两项合计166,699,008，不含header/对齐 |
| 常驻权重BO | 未分配 | 全驻留负载候选166,699,008；或按层/矩阵缓存，选择取决于G1实际预算，不能先假定能分配 |

| logits/测试采集 | 4,861,952 | 本次8×151936×4；若留256位置会增至155,582,464，不在性能跑中默认保存全量 |
| embedding / LM head额外buffer | 实测待定 | 源共享不代表各backend必共享物理buffer；检查TENSOR_DUPLICATED、mmap/非mmap加载路径 |

不可同时常驻两套完整模型：原模型质量基线、sidecar CPU、sidecar FPGA应顺序独立进程运行。导出器未来逐张量读取/量化/写出，不构造整模型FP32副本。当前诊断使用单个HF模型，原始BF16转FP32计算；不能将其内存消耗当板端量化运行时开销。

A3接入前的必查条件：跳过被替换MLP的原GGUF加载/预取、明确非MLP权重及共享head的buffer所有权、避免完整解包副本、BO生命周期与文件页分开登记、记录加载峰值与稳态RSS/PSS/CMA及驱动分配。释放mmap或madvise不能替代测量，也不保证BO或page cache立即释放。Linux/PL可能共享DDR，不能相加宣称独占容量。

无法在A2阶段仅凭文件大小证明整个模型能放入KV260；G1内存核验和A3真实驻留测量仍是必需项。
