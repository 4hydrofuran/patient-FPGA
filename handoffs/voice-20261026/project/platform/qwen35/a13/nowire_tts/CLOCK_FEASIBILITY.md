# 不改六根信号线、不拆板载24MHz：时钟可行性结论

结论：**音频采样共源在架构上可实现，不要求给PL另接MCLK，但不能靠现有a06仅改软件完成。** 推荐WM8960作唯一音频时钟主设备，PL新建过采样从接口，数据传输跟随codec帧事件。当前只是文档、算术及方向负例验证，未实现新RTL、未仿真或生成新位流，不能据此加载或试音。

这里的“同源”指ADC/DAC采样与I²S帧/位时钟同源；PS/AXI/PL系统时钟无需与codec物理同源，它们通过明确的异步采样/握手边界传输数据。固定22050→48000文件重采样不是ASRC，也不解决独立硬件时钟漂移。

## 推荐路线及已有连线

```text
板载24MHz → WM8960 PLL/SYSCLK → ADC/DAC、BCLK、DACLRC
                                      │ 现有H12/E10两根线，方向改为PL输入
PS约100MHz → 新PL过采样I²S从接口 ←──────┘
                 ↕ FIFO/帧事件、ready-valid
          按设备节拍传输的DMA → 内存
```

| 现有连接 | 新候选方向 | 处理 |
| --- | --- | --- |
| H12 ↔ P1.9 BCLK | WM8960→PL | 线不动；新PL必须输入，移除旧counter输出 |
| E10 ↔ P1.12 DACLRC | WM8960→PL | 线不动；新PL必须输入 |
| D10 ↔ P1.11 DACDAT | PL→WM8960 | 线和方向不变 |
| C11 ↔ P1.13 ADCDAT | WM8960→PL | 线和方向不变，录音后续单独验收 |
| B10/E12 ↔ SDA/SCL | IIC保持原方向 | 仍100k、3.3V开漏；E12不挪作音频时钟 |
| P1.10 MCLK / P1.14 ADCLRC | 仍不连接 | 保留24MHz；ALRCGPIO共享DACLRC，ADC/DAC同采样率 |

无需把H12/E10送入BUFG/MMCM：设计拟把它们当异步数据输入，在可靠的系统时钟下同步和边沿检测。不得为了在普通IO上拉时钟而添加`CLOCK_DEDICATED_ROUTE FALSE`。新的同步链属性、首级路径约束及IO预算必须依据真正RTL和布线验证；本轮未添加任何约束。

## 48kHz、16位双声道的建议新配置

保留24MHz参考；精确匹配内核PLL整数舍入模型：预分频2，N=8，K=0x3126e9，PLL输出约24.576MHz，SYSCLK再除2约12.288MHz，ADC/DAC各除256得到约48kHz。建议初版**16bit槽、16bit数据、双声道**，BCLK=32Fs≈1.536MHz，BCLKDIV=/8（字段7）；这匹配现有codec驱动S16双声道的bclk计算。I²S仍有一位延迟，不能把LRCLK跳变当作当位MSB，也不能在边界丢掉上一字LSB。

这是对旧a06的32bit槽/3.072MHz目标的**显式新设计选择**，不是旧位流已支持16bit槽。若坚持32bit槽，则BCLKDIV=/4、BCLK≈3.072MHz，须新驱动显式维护真实槽宽，不能沿用codec对16bit参数自动计算的32Fs。两者的WAV均为48k双声道S16；WAV不编码I²S槽宽。

上述值只供模型核对，不是可直接执行的寄存器序列；不修改现有机器驱动或GPIO方向，不切codec为主。不将PLL名义舍入误差与板载晶振精度混为一谈。[WM8960时钟/主从/共享DACLRC说明，第50–65页](https://mm.digikey.com/Volume0/opasdata/d220001/medias/docus/307/WM8960.pdf)。

## 为什么不推荐直接复用a06的I2S＋formatter

1. [AMD PG308 Unsupported Features](https://docs.amd.com/r/en-US/pg308-i2s/Unsupported-Features)明确列Slave mode不受支持。安装2026.1 revision11的封装/存根仍暴露`C_IS_MASTER=0`、`sclk_in/lrclk_in`，GUI Tcl还隐藏此参数。因此“能生成/综合”与“厂家支持并验证”不同；当前有文档与实际接口差异，不能把隐藏模式提升为生产可用。旧a06已经使用这个隐藏模式连接PL本地counter，旧实现通过仅保留为实现证据，功能不追认。
2. [PG330 Clocking](https://docs.amd.com/r/en-US/pg330-audio-formatter/Clocking)说明MM2S采样节拍来自aud_mclk。保留独立PS派生参考而只把codec改为主，不证明formatter与真实采样速率一致。FIFO只能吸收暂时差异，不是无限期频率锁定器。是否有特殊背压路径可让隐藏模式工作，仍缺厂家支持/RTL证据，不作为推荐路线。
3. a06 H12/E10仍由PL输出。直接先把codec切主可能造成双驱动，必须先有经验证的新输入型位流及安全切换/回滚序列，不能拿现在的位流探测codec主时钟。

推荐的新接口应使用固定双声道和固定格式，避免运行期跨域CHMUX与Fs-multiplier；DMA由codec帧事件消费/产生样本，而不是另建48k软件计时器。首版可只实现TTS播放，录音独立后续。通用AXI DMA/ASoC DMAengine是可评估候选，**尚未确认完整cyclic、TLAST/period、PCM格式与驱动接入**；不是现成可替换包。

## CDC如何处理，哪些仍未完成

- 现有三条CDC-6仍在旧a06中，**没有消除或豁免**。不再实例化旧模块的新方案可以避免这些特定配置跨域，但需新网表报告证明，不能提前记录0 warning。
- 新串行输入：BCLK/LRCLK/ADCDAT同步采样、边沿/位边界恢复、LRCLK整帧对齐；三信号延迟差、亚稳态MTBF、极端相位、I²S一位延迟和16/32bit边界要有真实RTL断言与仿真。
- 配置：固定profile，停止消费后提交完整快照；跨域时用request/ack或明确稳定协议；活动中拒绝更改。启动前FIFO预填，欠载/溢出可检测；缺BCLK看门狗应安全停止，不释放未知DMA。
- DMA：AXI ready-valid下不丢/重样，周期、最后一段、取消/复位、地址与IRQ及Linux声卡驱动均须实现/验证。跨CPU/PL依旧遵守唯一租约、双锁和正常结束链。

算术扫查采用明确**假设**：系统99–101MHz、codec频差±500ppm、BCLK高低各至少周期40%、边沿检测最多4系统周期。16bit槽最差仍约有209.9ns可供TX pad/走线/额外抖动（已扣10ns codec建立时间），32bit槽约79.7ns。仅说明存在预算，不是已经测得余量或保证亚稳态在4周期内消失；实际输出路径/线缆延迟未知，需STA/波形及可靠性计算。慢至10MHz的负例按模型被拒绝。

## 无板／必须实测／需要改线的分界

| 分类 | 本轮结果或后续事项 |
| --- | --- |
| 已无板完成 | 厂商限制与本地封装矛盾核对、PLL/槽宽/方向/节拍/时间预算模型、反例测试；TTS独立运行包及文件转换另列 |
| 仍可无板继续实现 | 新过采样RTL/同步与配置协议、按设备节拍DMA、Linux/DT候选；RTL仿真、综合实现、CDC/STA/驱动构建。此轮未声称完成这些实现 |
| 必须静默实测 | 实际电源轨/电流/唯一驱动、24MHz与BCLK/LRCLK频率占空比、IIC边沿、串行数据建立保持、DMA/IRQ与恢复；均NOT_TESTED |
| 推荐路线不需 | 新增信号线、挪E12、拆晶振或接P1.10。只改变新硬件/驱动中的时钟方向，需另行部署窗口 |
| 若坚持现有受支持AMD主模式 | 需要把共同MCLK送给双方等板级方案，涉及新增/调整连线与振荡器隔离，超出“不改线、不拆晶振”的约束，当前不采用 |

外接5V只改变取电安排，不改变此结论。当前仍3.3V总100mA、电流null，禁试音；明天供电切换由用户在断电和核对JP8/原3.3V断开/共地/3.3V信号后单独执行，并不自动允许加载此尚未实现的新方案。
