## 1. 建议采用的分工

**A 负责公共调用库、XRT 资源管理、平台链接和 ARM64 构建；B 负责优化计算核、内核适配资料、计算验证证据以及 B 候选打包。双方共同完成接口集成和候选验收。**

运行时采用一套有版本记录的公共实现。A07 的默认模块与 B04 的优化候选可以使用同一调用层源码，分别绑定经过核验的内核配置与 xclbin。计算内核发生替换时，公共 `sp_linear_v1` 接口保持一致。

该安排与 A 在 `B_MISSING_AND_DEFECTS.md` 中提出的边界一致：

> A07的XRT BO、sync、meta翻译/校验、错误隔离及平台链接由A实现；无需B先交完整六函数调用库。

原始 B04 同时要求 B 交付完整调用库、xclbin、ARM64 程序和自包含候选包。采用协作方案后，这些交付要求仍需满足，但可由 A 的公共成果与 B 的专有成果共同组成。**必须在验收记录中注明来源和责任方，不能仅交 XO 就宣布原始 B04 完成。**

本文件整理已有计划中的重合项并提出边界，不自动修改原任务包、公共契约、项目状态或双方的验收结论。

## 4. A 提供给 B 的最小交付

无需移交 A 的整个问诊工程。为了让 B 候选完整、可复现，A 至少提供：

1. **公共调用层**：准确源码版本或可访问提交、冻结头文件、构建入口、使用与分发说明。公共导出为 `open/load/run/report/unload/close` 对应的六个 `sp_linear_*_v1` 函数。
2. **B 核适配实现**：实际参数映射、BO 内存组选择、meta 解析与错误转换；记录采用的 B build_id 和私有 ABI。字段定义由 B 提供，运行时实现由 A 维护。
3. **目标构建材料**：平台与工具版本、链接配置、约定时钟、匹配 sysroot/XRT 信息；依赖不能打包时注明取得方式和摘要。
4. **匹配产物与日志**：B 候选 xclbin、ARM64 调用库及独立 host、逐文件摘要、实际构建命令与退出状态、实现报告。
5. **控制层测试证据**：正常生命周期、错误、超时、句柄与异常处理的测试结果；公共 report 的 execution_kind 按契约使用 CPU_REFERENCE / FPGA_REAL。mock 测试另外醒目标注为替身测试，不新增公共枚举值，也不标记为 FPGA_REAL。

如果 A 暂时只交付实现骨架，应逐项标明未完成内容。B04 仍可推进资料整理、数值回归和打包准备，但相关验收项继续保持未完成。

## 5. B 提供给 A 的最小交付

1. **唯一候选**：double 的实际 XO、对应源码、私有头、kernel.xml、构建配置与 SHA256。
2. **核适配说明**：参数索引/名称/方向、尺寸计算、padding、字节序、meta 字段偏移与状态语义、job_id 和完成计数规则、build_id；以实际源码和 XO 元数据为准。
3. **主机检查边界**：哪些非法输入由公共调用层拒绝、哪些错误由核返回；例如有效 W 区中的 −8 处理与其他数值检查的既有边界，不自行扩展私有 ABI。
4. **测试与证据**：固定输入、独立 expected、原始 RTL 输出、回放入口及必要报告。优先使用已交付的补交包，保留历史追溯限制。
5. **风险与修复支持**：HLS 负 slack、未测的 AXI 内部 FIFO 峰值及实现/板测状态；遇到核问题保留复现，修改后更新版本和相关回归。

## 6. 共同遵守的运行边界

- 调用方传普通主机数组，公共运行时负责转为 XRT 管理的缓冲区；不直接把普通虚拟地址当成硬件可访问地址。
- load 成功后运行时拥有或复制所需权重；调用方可以释放原数组。权重使用直到对应 unload，容量与缓存策略有明确预算。
- 每个上下文仅允许一个在途 run；同一设备的候选替换在确认任务结束的维护窗口进行，避免竞争配置和资源。
- 检查实际 meta 的 magic、build_id、job_id、状态、完成标志及计数，拒绝旧结果和错误核版本。首次 meta 清零；失败时不消费 Y。
- 超时只表示本次等待期限已到，不证明硬件或 DMA 已停止。上下文进入 poisoned 后拒绝新任务；未经确认停止，不释放仍可能被访问的缓冲区。无法安全关闭时按契约返回 BUSY/POISONED 并保留所有权。
- C++ 异常不得越过公共 C ABI。错误码及报告字段按冻结契约处理。
- report 支持 required_bytes 查询（含结尾 NUL），缓冲不足不输出半截 JSON。报告保留契约规定的版本、摘要、任务、状态、执行类型、完成计数、驻留、分段耗时及字节/周期字段；未测值填 null。后端未执行输入量化时 quant_ms 为 null，由模型运行时另记并在整机汇总中计入。
- bias、SiLU、门控乘法、残差、RMSNorm 和模型状态由模型运行时处理；B 的公共计算接口接收约定的量化输入并返回线性计算结果。
- PC、Csim、综合、RTL、实现、ARM64 构建和 BOARD 分域记录；未测值保留 null/NOT_TESTED。CPU 或 mock 通过不能证明真实 BO、PL 或板端恢复可用。

| G1 契约一致 | 六函数实现、公共头和 ABI 检查 | 候选契约一致、私有 ABI 映射完整 |
| G2 正常调用 | 初始化、加载、重复计算、报告、释放的主机层测试 | 使用约定向量核对数据格式和数值 |
| G3 失败路径 | 非法参数、短缓冲、无效句柄、并发提交、异常、超时及 stale meta 测试 | 核错误语义与实际证据核对，既定数值门槛不放宽 |

时序是否达标以真实实现报告和约定时钟目标为准。HLS 估计值单独保留，不能替代实现结果；实现后不达标不能记为实现 PASS。

## 9. 推进顺序与工作量

1. **核对可复用成果**：确认 A 公共调用层的实际版本、完成项、平台材料及缺项；B 对应提供核适配说明。B03 接收复测可并行，不倒签验收。
2. **完成调用层适配**：A 接入 B 私有参数/meta，运行正常与负路径测试；B 核对语义和向量。
3. **构建目标候选**：A 执行 B 候选的链接、布局布线和 ARM64 构建；B 处理核相关问题。高内存构建串行安排，软件资料工作可并行。
4. **联合回归和打包**：B 组织候选包，双方检查来源和完整性，独立目录复核后逐项记录 G1～G6。
5. **进入板测准备**：保持 BOARD 未测状态，待匹配平台和独占窗口具备后进入 B05。

工作量为工程预算，工具等待与重大平台问题另计：

| 方案 | B 侧有效工作量 | 前提及限制 |
|---|---|---|
| B 独立完成原始 B04 | 约 40～70 小时，6～10 个工作日 | 包括完整调用层、生命周期、链接、ARM64 和打包；时序/平台重大问题可能增加数天 |
| A 公共成果已可用的协作方案 | 约 16～32 小时，2～4 个工作日 | B 做适配资料、集成支持、核回归和打包；A 的实现、链接与构建工作仍真实存在 |
| A 公共成果尚未完成 | 不按上述 2～4 日承诺整个 B04 完成 | 记录 A 待交项和预计时间；核相关修复及实际工具耗时以首轮结果更新 |

协作节省来自公共实现复用。它不表示把 A 的剩余开发与等待从项目总工期中删除，也不把 B03 的内核加速直接换算成整机收益。
