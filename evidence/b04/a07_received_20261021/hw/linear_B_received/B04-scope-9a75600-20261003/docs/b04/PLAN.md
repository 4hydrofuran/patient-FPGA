# B04 分阶段开发与验收

起点：2026-10-03，B03 double 已冻结；B03 证据与实际补交包已发布。工作分工采用 A07/B04 边界：A 主责公共调用层、XRT 生命周期、平台链接及 ARM64 运行时构建；B 主责计算核资料、独立适配验收、候选组装和交付。

## 阶段 P1：冻结核适配资料

- 从实际 XO 的 kernel.xml 提取 17 个参数、AXI-Lite 偏移、端口和物理宽度。
- 编译核头的结构布局探针，确认私有 meta 40 字节、字段偏移与候选 build_id。
- 写入可供 A 使用的版本化 kernel profile、缓冲区尺寸、状态映射及运行约定。
- 检查源码、头、配置、XO 与 B03 冻结摘要一致，不修改核或公共契约。

## 阶段 P2：B 侧独立适配验收

- 提供无 XRT 依赖的尺寸与私有完成记录验收工具。
- 验证边界尺寸、短缓冲、错 magic/build/job、完成标志、计数及私有错误码。
- 使用独立构造的字节记录和已归档 RTL 数据检查拒绝旧结果及失败不消费 Y。
- 复用已验证 B03 数值与 RTL 证据；新增检查如实标为 PC/控制层资料验收。

## 阶段 P3：候选组装与解压复核

- 实现清单、摘要、依赖和阶段状态校验；支持导入 A 的准确产物。
- 验证 ARM64 ELF、六个公共导出符号、xclbin/核版本和契约的对应关系。
- 缺少 A 成果时输出明确标注的 B 侧阶段包；完整候选只能在全部无板门槛满足后命名为 B_pc_candidate_v1.zip。
- 在新目录解压、重新编译自测并核验逐文件摘要，提供可复现说明与收据。

## 阶段 P4：A/B 集成验收

- 接收并核验 A 的公共库源码、实际 xclbin、匹配 ARM64 库/host、平台材料和控制测试证据。
- 核对 G1～G6，分别记录 B 贡献与 A 贡献；未得到实际证据的项保持未完成。
- 真实实现时序、ARM64 运行时和 BOARD 不由 B 侧静态工具代签。
