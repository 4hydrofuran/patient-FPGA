## 3. A10与A11：建立了什么基础

A10已发布的是 `PASS_MINIMAL_WITH_LIMITATIONS`。固定Linux `6.8.12-a10irq2`、XRT 2.18.0及2026.1工具路线。一次真实向量调用和正常退出恢复形成最小闭环，流程15.228秒，采样温度峰值32.624℃。44项PC方法不是44次板测。已取消的20长度/1000回归、长压、完整内存包络、带宽功耗及在途DMA故障不被追认为通过。

A11将该基础推进到真实MLP：手算1次、尾块/双scale1次、实际gate/up/down各7次，共23次有效调用。全部原始FP32 Y保留并由主机独立核对，最大绝对及相对误差均0。额外T=0拒绝返回SP_BAD_ARGUMENT，输出哨兵未改变，不计为有效硬件提交。

首次open错误8的实际原因是4096字节sx BO被分配到低2GiB之外的高DDR。派生实现把私有记账对齐改为8192字节，保留低地址、尺寸及预算限制，经单变量open/close验证后继续。4个IO BO复用，峰值14个主机BO、2162688字节。

A11服务时间示例：T=1中位gate/up/down约5.263/5.268/5.109毫秒；T=8约16.764/16.753/15.257毫秒。服务时间包含量化、BO同步、提交轮询、meta及输出检查和返回复制，不能当作纯PL核执行周期。

## 4. A12模型路径与prefill流程

目标为 `Qwen/Qwen3.5-0.8B`、文本非思考模式。固定模型revision为 `2fc06364715b967f1860aea9cf38778875588b17`，运行时基础commit为 `81e39ad34368329b5db77620721510fd91107e80`；派生源码必须再核对各窗口manifest。公共契约SHA256为`83bd402b39350710d8689d50f79296e9625e9c75ccb0ecee145f08067c4ee3b6`。

应用先路由学生问题，构造提示词并原生分词，随后准备R0状态或恢复前缀快照，再做prefill、首token及decode。24层中18层线性注意力、6层完整注意力保留CPU计算；PL仅承接每层MLP的gate/up/down，共每微批72次投影。CPU仍负责注意力、归一化、激活、残差、输出头及大量调度工作。

每次PL调用之外，管理端进行新鲜身份/租约/双锁、内核健康、温度、内存及资源预算检查，并持久记录许可。后端执行量化、输入同步、核提交、meta与输出同步/核验。模型真实消费返回的PL结果，已经由A12步骤08、09同ARM数值/混合状态对照证明其受测范围。

普通应用已经关闭完整诊断转储、细分profile及全状态指纹，仅保留普通所需末位置logits与安全检查。详细诊断请求另开全位置投影/logits/状态输出，离线再做严格全字节核对。减少诊断文件不会自动减少普通应用逐调用许可成本；减少许可成本也不会自动解决诊断读取缓存。

## 7. CMA失败的证据、解释与暂停修复

失败点：CmaFree降至47392 KiB，低于原98304 KiB（96 MiB）门槛，拒绝继续；门槛未降低。CmaTotal仍800 MiB，MemAvailable门槛1114112 KiB，显式BO仍148个/134.08 MiB。

CMA是供设备申请物理连续内存的一块预留区域，属于系统DDR的一部分；它既不是全部CPU可用内存，也不是磁盘。Linux可暂将其中可迁移页用于别的用途，因此全局可用内存较多时，CmaFree仍可能偏低。文件总量不等于驻留页缓存，更不等于实际CMA占用。

| 窗口 | 最低已观测CmaFree | 诊断原件总量（CPU＋PL） |
| --- | ---: | ---: |
| CPU00 health | 321.84 MiB | 本窗未开原始诊断 |
| CPU02 | 145.17 MiB | 83.13 MiB、888文件 |
| TT10-00 cpu02 | 153.37 MiB | 83.13 MiB、888文件 |
| TT10-01 v3 | 46.28 MiB，拒绝 | 1163.32 MiB（1.136 GiB）、9975文件 |

增长来自新增70-token warm、107-token全R0及37-token hit的长序列完整诊断；旧02只有短9-token诊断。尤其全位置大词表logits会同时增加CPU输出头计算、转储及核对量。模型权重未因此增长，CPU02管理优化不是这14倍原件增长的同一个变更。

每后端长对照读取4541个不同文件、544944148字节（519.70 MiB）。CPU结果到CASE_FINISHED约34.466秒，邻近样本CMA降263.65 MiB；PL约35.221秒，降261.77 MiB，而MemAvailable分别只降8.87/3.29 MiB。该段无新增PL许可，显式BO/权重记录不变。这支持诊断读取及预读形成可迁移页缓存、占用CMA页的假设；没有段内逐步采样和逐页归属，尚不能认定唯一原因或全部下降均由页缓存造成。

source-04写端原已逐文件fsync＋DONTNEED；原读取端普通buffered read会再次把文件带入缓存。读取块限制用户态缓冲，不限制内核页缓存。前缀有效快照约21.04 MiB；192 MiB为两槽及暂存规划上限，不是已实际分配的192 MiB BO。
