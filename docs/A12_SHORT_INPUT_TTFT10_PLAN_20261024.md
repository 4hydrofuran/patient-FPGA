## 1. 目标与适用范围

### 1.1 目标

**模型与运行进程就绪后，受支持的短输入多轮请求，应用收到真实模型首token的时间不超过10.000秒。**

- 用户主要关注后续多轮交互；允许恢复与实际输入精确匹配的前缀状态，再计算本轮变化的后缀。
- 优先保留Qwen3.5-0.8B、非思考模式、现有权重、数学/ABI、物理T≤8及现有PL核。先减少重复工作，再减少每个新token的执行成本。
- 第一阶段工程目标是将常见请求的**未缓存后缀控制在16—24 token**。这是优化方向，不是当前已达到的输入分布，也不是删除超限样本的条件。
- 性能通过与数值/回答质量/状态/恢复通过分别记录。子任务完成不代表10秒目标达成。

### 1.2 计时边界

主指标定义为 `TTFT_app = t_first_token - t_request_received`：

| 时点/指标 | 固定定义 |
|---|---|
| `t_request_received` | 应用收到完整、已确认文本请求；在本轮路由、提示词构造、分词、缓存查询、恢复、计算之前 |
| `t_first_token` | 应用接收到本轮真实模型生成的首token事件 |
| `TTFT_native` | 原生worker的请求/首token区间，保留为子指标 |
| 完整生成 | 应用收到正常EOS/最终结果的时间，另记耗时 |
| 有效回答完成 | 内容检查完成的时间，另记耗时 |
| 语音首声 | 独立指标；本计划不把TTFT等同于可播放或已出声 |

原107-token板测从管理器发送worker请求前开始，未覆盖完整应用路由/模板/现场分词。新主指标比原计时边界更完整；历史数字用于工程定位，不能直接宣称新应用指标已通过。

请求到达后的等待、缓存恢复或重算计入TTFT。模型加载、权重一次性加载、服务启动时公共前缀预计算另记为启动/预热；服务只有完成这些工作后才能声明就绪。保留现有单活动请求策略，并记录忙拒绝、超时和失败。

### 1.3 验收分组与严格时限

- **正常短输入热请求**：主验收组，按TT10-00冻结的真实工作负载统计，全部有效模型请求应满足TTFT_app≤10秒。任一超限即记目标违例，不能以均值或p95通过覆盖。
- **热请求中的缓存未命中/计划内失效**：保留在热请求总表，单列命中状态及R0重算耗时；超过10秒仍算违例。不能只报告命中的样本。
- **冷启动首轮、进程重启后首轮**：单列加载/预热/首轮墙时，不与后续热请求混报；当前不承诺冷启动10秒。
- **长输入/超支持边界**：单列功能和性能。进入该组的规则须先冻结；原开发集中的慢样本不得测后改归长输入。
- **模板、策略拒绝及错误响应**：按实际来源记录，不计为模型请求已达到10秒。

TT10-00以原17条开发输入及有代表性的短问题变体建立支持集，初始覆盖总提示约128 token以内的短问答，并保留上下文1024容量和尾块的正确性边界。有效后缀按1—8、9—16、17—24、25—32、33—48、49以上分桶；各桶都保存结果。最终支持范围及样本清单在性能采集前冻结。

最终至少取得100个有代表性的正常短输入热模型请求，覆盖全部17条开发问题及冻结变体；计划内取消、切换、缓存失效另作场景并报告。给出每条原始记录、样本数、p50/p95/最大值、超10秒数量、命中率、完整回答及decode。测试集通过不是所有可能问题的实时性证明；支持范围和限制随结果公开。

## 5. 延迟预算与可行性判断

以下是**有效后缀≤24 token时的工程分配目标，全部待测**，不是预测值或已通过指标：

| 区间 | 目标预算/秒 |
|---|---:|

| 逐次许可管理 | 2.0 |

| 检查、量化与桥接搬运 | 1.0 |
| 首token选择与事件传递 | 0.2 |
