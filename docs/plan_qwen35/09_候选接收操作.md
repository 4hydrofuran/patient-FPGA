# 只在约定节点接收候选
## 平时
各成员读自己的状态和共同规格；不要求主线每天拉取B/C分支，不要求B/C克隆A完整工程。
公共规格就在三个个人包中，数学和软件接口相同。模型/依赖各自从公开源取得并记版本。

## 交付时
B/C把一个自包含候选zip交给A，另附sha。渠道可以现有共享盘、Git仓库Release或文件直传；本计划不以云仓库创建成功为前提。
默认包保留，候选先解压到新的incoming目录，检查压缩包路径安全和目录清单，不覆盖系统。
在已解压且确认安全的目录执行：
```bash
python docs/plan_qwen35/tools/verify_bundle.py incoming/candidate --contract docs/plan_qwen35/contracts/contract_lock.json
```
最终板测候选加：
```bash
python docs/plan_qwen35/tools/verify_bundle.py incoming/candidate --contract docs/plan_qwen35/contracts/contract_lock.json --require-board
```
此命令确实随本包提供，但只做静态校验；它不执行selftest、不安装模型、不证明哈希正确的代码就安全或功能正确。

## 选择时
静态检查→确认入口与安装边界→独立自测→同板统一测→ACCEPT/REJECT/INCONCLUSIVE。
A只需读manifest/摘要和测试失败关联文件。合格后选整包库+核或独立语音worker，业务API和评分不改。
选择动作发生在服务停止、硬件空闲的维护窗口；超时的设备先恢复，不能立即dlclose释放BO。
需回滚时恢复上一份选择配置并按已验证步骤重启，绝不只把库换回去而留下不同版本位流。
