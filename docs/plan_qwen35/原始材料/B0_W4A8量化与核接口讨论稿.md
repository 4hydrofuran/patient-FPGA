# B0 W4A8 量化与核接口讨论稿

版本：讨论稿 0.1　日期：2026-09-26　状态：**待 A/B/C 评审，不是冻结的 v1 ABI**

## 1. 用途和范围

本文供 B 与 A 核对量化数学、权重字节布局、HLS 核调用及验收样例。B 据此实现独立黄金参考和 HLS 核；A 据此实现权重导出、CPU 同数学后端和 XRT 主机调用。C 只需确认业务 API 能准确区分真实硬件执行、主动选 CPU、错误回退和未测试状态，不接触权重字节。

首版核只计算 Qwen2.5-0.5B-Instruct 目标 MLP 的线性层。bias、SiLU、RMSNorm、RoPE、残差、attention、KV Cache、采样均在 PS 按模型原顺序处理。`fpga_required` 表示声明的目标 MLP 必须由 PL 完成；它不要求原本留在 PS 的算子进入 PL。

来源：项目《KV260 三人完整执行手册》“接口契约草案 v0.1”“三人30项任务总表”，《04_B_PLUS_HLS_任务与提示词》B0—B4，以及《KV260 离线标准化病人项目策划书》量化与算子接口章节。本稿保留其既定主线；下文标为“待确认”的字段不能由 B 单方冻结。

## 2. 量化计算规则：拟作为 v1 固定部分

### 2.1 逻辑矩阵

- 输入浮点激活 `X[T,K]`，权重 `W[N,K]`，输出 `Y[T,N]`，逻辑上计算 `Y = X × Wᵀ`。
- 首版 `T` 的合法范围为 `1..8`；先交付 `T=1`，再验证 `T=2..8`。`N`、`K` 必须为正且落在正式核容量表内。
- `Kp = ceil(K/128) × 128`，`Np = ceil(N/32) × 32`。填充元素参与核内固定长度循环，但不参与量化尺度估计。无效权重和输入元素填 0；无效输出列必须写 0。
- 一个逻辑权重矩阵对应明确的模型层名、原始 shape、是否转置、来源 revision 和哈希。A 导出时逐张量核对，不仅依赖文件名猜测。

### 2.2 W4、A8 与尺度

- W4：每个输出行 `n`、每 128 个 `K` 元素为一组，对称有符号量化。有效码值为 `[-7,7]`；4 bit 码 `-8` 保留为非法值，不能作为正常权重。
- A8：每个 token 的整条有效 `K` 向量使用一个尺度，对称有符号量化。有效码值为 `[-127,127]`；`-128` 不作为正常激活。
- 零点均为 0。权重组尺度 `Sw[n,g] = absmax(W[n,该组有效元素])/7`；激活尺度 `Sx[t] = absmax(X[t,有效K元素])/127`。
- 全零权重组或全零激活向量：尺度置 1，量化码全 0。NaN/Inf 在导出或发起计算前拒绝，不得默默量化为 0 或饱和值。
- 量化舍入为 nearest, ties-to-even（恰好在两个整数中间时取偶数）；舍入后分别夹到 W4 与 A8 的合法码值范围。必须用确定测试检查正负的 `.5` 边界。

### 2.3 累加和还原

```text
G = Kp / 128
Wq[n,k] = clamp(round_even(W[n,k] / Sw[n,k//128]), -7, 7)
Xq[t,k] = clamp(round_even(X[t,k] / Sx[t]), -127, 127)

S[t,n,g] = Σ(r=0..127) int32(Wq[n,128g+r]) × int32(Xq[t,128g+r])
Y[t,n]   = Σ(g=0..G-1) float32(S[t,n,g]) × Sw[n,g] × Sx[t]
```

`S` 在**每个 128 元素组内**用有符号 INT32 累加。单组最大绝对值为 `128×7×127=113792`。不同组可能有不同 `Sw`，因此必须先对各组还原尺度，再合并为输出；不能先把不同组的 `S` 相加，再乘一个尺度。bias 不在核内处理，PS 按原模型语义只加一次。

验收分两层：整数部分和 `S` 与独立参考 **bit-exact**；最终 FP32 输出使用冻结容差。现有草案建议起点为 `max|Ypl−Yref| ≤ 1e-4 + 1e-5×max|Yref|`，但需在开发集确认后、正式评测前冻结。浮点乘法结合顺序、组求和顺序与溢出/非有限结果策略仍需 A/B 明确（见第 7 节）；不能在看到失败结果后临时放宽门槛。

## 3. 字节布局：拟作为 v1 固定部分

所有文件和跨进程字段采用小端序，并附长度与版本校验。长度以**字节**计，不以元素数计。

| 缓冲区 | 逻辑内容 | 线性存储 | 长度公式 |
|---|---|---|---|
| `w_packed` | W4 权重 | `[输出32行tile][K的128组][组内k][16个行对字节]` | `Np × Kp / 2` 字节 |
| `sw` | 权重尺度 | FP32 `[输出32行tile][K组][32个lane]` | `Np × G × 4` 字节 |
| `xq` | 输入激活 | INT8 行主序 `[T,Kp]` | `T × Kp` 字节 |
| `sx` | 激活尺度 | FP32 `[T]` | `T × 4` 字节 |
| `y` | 输出 | FP32 行主序 `[T,Np]` | `T × Np × 4` 字节 |
| `meta` | 核写回状态 | 结构体布局待冻结 | 待定，调用方传实际字节长度 |

权重字节寻址按以下公式；这里的“偶/奇”指**同一个 `k` 的两个输出行 lane**，不是相邻两个 `k`：

```text
nb = n // 32
g = k // 128
r = k % 128
lane = n % 32
byte_offset = (((nb × G + g) × 128 + r) × 16) + lane // 2
shift = 0 if lane % 2 == 0 else 4
Sw_float_index = (nb × G + g) × 32 + lane
```

偶数 lane 放低半字节，奇数 lane 放高半字节。解码半字节 `v`：若 `v < 8`，值为 `v`；否则值为 `v−16`。正常输入不得出现代表 `-8` 的半字节 `0x8`。`n≥N` 或 `k≥K` 的权重填 0，填充行的 `Sw` 填 1。`xq` 尾部填 0；`y` 的 `n≥N` 列必须为 0。A 的导出器、B 的独立参考和 HLS testbench 应逐字节比对这些规则。

## 4. 可手算的共同样例

这个样例用于 A/B 第一次对表。它有意采用很小的逻辑矩阵，但按正式规则填充到 `Kp=128`、`Np=32`。所有未列出的权重和激活码均为 0。

```text
T=1, K=2, N=2, G=1
W[0,:] = [ 7, -1]    Sw[0,0] = 1
W[1,:] = [-7,  2]    Sw[1,0] = 1
X[0,:] = [127, -1]    Sx[0]   = 1

Wq[0,:] = [ 7, -1]
Wq[1,:] = [-7,  2]
Xq[0,:] = [127, -1]

S[0,0,0] = 7×127 + (-1)×(-1) = 890
S[0,1,0] = (-7)×127 + 2×(-1) = -891
Y[0,0] = 890.0
Y[0,1] = -891.0
```

字节检查：`w_packed[0] = 0x97`（`k=0`，低半字节 `7`，高半字节 `-7`）；`w_packed[16] = 0x2F`（`k=1`，低半字节 `-1`，高半字节 `2`）。`sw` 的前两个 FP32 值为 `1.0, 1.0`；`xq` 前两字节为 `0x7F, 0xFF`；输出前两列为 `890.0, -891.0`，其余30列为 `0.0`。此例只证明打包与单组计算，不能代替跨组缩放、舍入和尾块测试。

建议 B 在 B1 再提交三类最小反例：①两组 `Sw` 不同，能识别“先跨组求和后缩放”的错误；②正负 ties-to-even，例如 `2.5→2`、`3.5→4`、`-2.5→-2`、`-3.5→-4`；③ `K=129`、`N=33`，能识别组边界、tile边界和填充错误。每个反例保存原始输入字节、预期部分和、预期输出与随机种子。

## 5. 核调用接口草案

工作名 `w4a8_linear_v1`。建议采用 `ap_ctrl_hs`、AXI4-Lite 控制和 `m_axi` 访问由 XRT 管理的 DDR 缓冲。A/B需用目标 2026.1 工具生成的 kernel metadata 确认参数顺序及 memory group，主机不得手抄寄存器偏移，也不得把用户态虚拟地址直接作为硬件地址。

逻辑参数顺序建议固定为：

```text
w_packed, sw, xq, sx, y, meta,
T, N, K,
w_bytes, sw_bytes, x_bytes, sx_bytes, y_bytes, meta_bytes,
job_id, abi_version
```

主机应先检查维度、缓冲长度、乘法溢出、ABI版本、目标 shape、指针及 BO 所属设备，再同步输入 BO、发起计算、有限等待、同步读回输出和 `meta`。核内也应做容量边界检查。实际参数 C/C++ 类型、每个指针的数据宽度、对齐要求、m_axi bundle/group、最大 `T/N/K`、最大 BO 长度和错误码由 A/B 在 `kernel_v1.yaml` 中冻结；上述列表目前只是**逻辑顺序**。

`meta` 至少要让主机核对：ABI magic、`kernel_build_id`、回显的 64 bit `job_id`、状态、完成标志、硬件成功完成计数、算法请求权重字节数。发起前主机用哨兵值填充并同步 `meta`，完成后核对 `job_id` 和当前位流版本，防止读到上一次任务的结果。`hw_completed_count` 只能由核在成功完成时递增；位流重载/核复位后的清零语义须冻结。主机自增序号不能冒充硬件完成计数。

核周期和实际 AXI 传输字节必须来自经过核对的硬件计数器或受支持的 profiling；若暂未实现，报告中填 `NA`。`algorithm_weight_bytes` 是按逻辑工作量计算的请求量，不能标为真实总线字节数。测时至少区分：BO分配、首次权重加载、输入量化及同步、核执行、输出同步、完整服务时间。权重应按层或受控块常驻 BO，避免每 token 重传全权重。

## 6. B0 到首次板测的交付与验收

| 关口 | B交付 | A核对/接收 | 不可替代的证据 |
|---|---|---|---|
| B0（9/28前） | 共同手算样例、边界反例、未决问题清单 | 签认量化与接口 v1，生成机器可读契约 | 双方对同一字节和结果的书面确认 |
| B1 | 独立 Python/C++ 黄金参考、固定向量及哈希 | 用相同向量核对导出器和CPU参考 | 独立算法，不调用被测导出器/核产生期望 |
| B2 | 最小可综合 HLS 核、Csim/Cosim、`.xo`候选 | 核对平台端口和构建信息 | Csim、协同仿真日志与失败输入 |
| B3/B4 | 真实形状的 `.xo`、metadata、报告，与A联合板测 | 链接 `.xclbin`、XRT运行和错误恢复 | KV260身份、位流哈希、真实MLP输入输出与比较日志 |

一个核能编译、Csim通过、Cosim通过、布局布线收敛、真实板测通过是五种不同状态。G3必须有真实KV260上的目标MLP尺寸、包含必要搬运的时延和数值对照。真实模型生成使用PL是A5的后续验收，不能用G3孤立层测试代替。
