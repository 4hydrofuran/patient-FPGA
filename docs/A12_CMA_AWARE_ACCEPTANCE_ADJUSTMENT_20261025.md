## 2. 这次先跑什么，哪些暂不混入

首个未来计算窗口仅做 **RESOURCE_PROBE：普通路径资源探测**。前提仍是现场故障已另行处理、新鲜计算健康基线、唯一租约/双锁及新计算授权。最新共享状态不能证明当前板卡可安全开工，本轮不操作现场。

使用明确冻结的 source-04 原生版本和配套受测库，保留原逐投影许可、fsync、健康门禁及 B 核。先不改变授权协议和安全检查频率，避免把资源问题、日志优化及计算变化同时混在一个样本里。新控制编排先完成无板验证。

第一轮顺序：

1. 加载权重，确认实际148个显式 BO、72份权重及地址/预算；记录启动与驻留后的资源。
2. 普通 R0：无前缀命中，得到同一冻结输入的真实输出和初步时延。
3. 轻量 warm：正常计算并捕获内存中的完整混合状态与末位置 logits，完成必要身份/完整性检查；不生成长投影和全位置 logits 文件。
4. 普通 hit：恢复同身份快照，计算剩余输入；保留缓存命中、复用/新算 token、实际调用、末位置 logits、输出 token/EOS、内容检查和活动状态清理证据。
5. 验证一对成功且余量符合预算后，才进行预先列明、次数有上限的连续请求观察；不自动扩成长压。每轮记录失败，不筛掉慢样本。
6. 正常关闭、设备释放及默认平台恢复独立确认；未知 DMA 或失败锁存不因试验结束而清除。

普通请求固定：`logits_mode=final`、`profile=false`、`diagnostic_report=false`、不设置 diagnostic_dir、不启用 diagnostic_all_layers / dump_state / state_fingerprint / a12_consumer_trace。保留模型运行必需的前缀状态、完整性验证、BO同步及逐投影完成/meta/输出核验。

这不是把所有诊断义务取消：首轮普通输出和末位置结果的对照，只证明它们的受测范围；完整中间值/混合状态和新变更的必要证明另行收口。RESOURCE_PROBE 数据可报告为“普通路径实际测量/探索结果”，不能直接写成正式性能或数值总验收 PASS。

**该窗口不调用 DiagnosticReader，不读取519.70 MiB旧原件，不生成 FILE_HASHES 大扫描，不执行 diag_exact/full_R0/hit 长诊断链，也不把修复暂停候选作为入口依赖。** 正常启动必需的制品身份校验仍执行，并单列其I/O与资源变化。

## 3. 完整数值取证单独完成，主核对搬到电脑

现有完整数值要求不降为只看一句话、抽样或只比较旧摘要。后续确需新增完整证据时，拆成三个明确阶段：

| 阶段 | 板端执行 | 不再混入的工作 |
| --- | --- | --- |
| 有界数值采集 | 同一冻结模型/输入/数学/采样策略，采集要求覆盖的全部原始投影/logits/状态；原阈值与完成核验保留 | 不边采完整长诊断、边跑普通性能请求 |
| 安全关闭后受控回传 | 先证明无在途提交和设备安全释放，再逐文件/有界批次读取传输并计算新SHA，保留板端原件 | 不把CPU与PL的全部原件又在模型驻留时重扫几遍；不在板端构造整包内存对象 |
| 电脑完整核对 | 对完整回传原始字节执行原拼接、全位置logits、混合状态、长度/位置/身份核对和损坏拒绝 | 不在板卡上进行主要的519.70 MiB全量比较和重复FILE_HASHES读取 |

回传必须覆盖该次验收所需全部原件；现有发布包只有选择性文本和部分回读文件，不能当作完整数据。新SHA用于校验传输和身份，电脑核对仍实际读取全部所需字节，不能由manifest或SHA相同就补造未读数据的PASS。

回传读取也会改变板端缓存，因此仍采用有界读取、同FD的文件缓存建议、内存观测及背压。传输/校验结束后到下一计算窗口之间，重新检查实际健康和余量；分窗口本身不保证缓存已经回收，不靠重启或drop_caches清场。

写端采集仍可能产生内存压力，不能因“核对移走”就假设零开销。采集前计算文件总量、最大文件、状态暂存和观测工作区，并依据实际余量设上限；逐文件完成后沿用已验证写端处理。DONTNEED 不保证实际释放，返回0不作为继续采集的充分条件。[Linux posix_fadvise 文档](https://man7.org/linux/man-pages/man2/posix_fadvise.2.html)

如果一次全量采集仍超出已证明资源包络，停止扩大试验，先设计按层/位置/数据类别的有界采集。每片由相同冻结请求从明确R0或匹配前缀状态确定性重放，只选择导出的证据范围；覆盖清单必须包含全部要求的 layer/op/token/state，电脑核对无缺片。该诊断改动需独立验证，不能靠删掉失败层或抽样来通过。额外重放的PL次数和验收时间如实计入，正常使用不承担这些成本。

## 4. 用资源轨迹区分问题，不再靠调用总数推断

观测点设在：启动身份读取前后、BO/权重驻留后、R0前后、warm/capture后、hit lookup/restore后、每个请求交付后、worker关闭后，以及独立诊断写入/回传前后。

资源记录至少区分：

- CMA：CmaTotal/CmaFree，实际显式 BO 分配/地址/字节及驱动错误。
- 普通内存：MemAvailable、Cached、Dirty、Writeback；manager/worker 的 RSS，必要阶段点的 PSS。
- 前缀：实际槽数、有效状态/末位置logits字节、保存恢复暂存的已观测或未测峰值；192 MiB 仍只是规划上限，不是现成可释放的BO。
- I/O与观测：每阶段读写字节/文件数、回收建议及前后采样、观测日志字节/耗时；PL提交与完成变化另列。

普通窗口的观测使用固定容量内存计数和有界日志；完整 PSS/FD/VMA 扫描留在必要阶段边界，不为每投影/文件新增大对象、全局扫描和同步落盘。保留既有健康观察；记录新观测自身的成本，先用无板fixture检查它不会制造另一条无界分配路径。

判断分支：

| 观察 | 后续处理 |
| --- | --- |
| 无诊断普通 R0/warm/hit 有稳定余量，诊断写入或回传才明显下降 | 主路径继续推进；诊断I/O独立修复并验证，不能宣称全部CMA原因已排除 |
| 普通路径本身持续下降，或有新的BO分配/驱动错误 | 暂停时延优化，按状态/运行时/隐式资源生命周期定位，不能继续归因于原件核对 |
| warm/capture或restore单独造成超预算峰值 | 查实际快照及暂存生命周期；保留完整混合状态语义，不能只删KV/递归状态来过关 |
| DONTNEED返回成功但余量未恢复 | 视为回收效果未证明；停止按原门槛拒绝的后续工作，不循环整理缓存直到过线 |

CmaFree≥98304 KiB、MemAvailable≥1114112 KiB及前缀阶段原有额外余量保持。首次触发即锁存，不减门槛、不将失败改为告警、不自动重放。采样最低值与连续最低值区分；少量成功不能证明长期无泄漏。通过范围以真实完成的连续请求数、余量和关闭证据为限。

## 5. 后续工作的顺序与交付

1. **无板准备**：冻结普通探测输入/制品，完成轻量编排、观测和关闭故障路径的相关测试；新短提示词先独立重新分词、绑定身份及内容验证。第一轮旧输入只用于延续既有证据和定位，后续不得把它当新提示词验收。
2. **普通资源探测**：先实际完成缺失的普通PL R0/hit和正常关闭，得到CMA轨迹与输入到有效回答的探索时延；不以长诊断成功作为它的前置。
3. **必要数值收口**：按变更影响引用旧证据并补齐真正缺少的完整数据；有界采集、受控回传、电脑全量核对。诊断读取候选若继续使用，其当前tip必须重新完成最终无板验证；早期33/35项结果不自动覆盖后来修改。
4. **逐项减少管理成本**：请求日志 → 检查位置 → 微批授权，每轮保持同一轻量请求/工作量，独立归因；不同时更换提示词、核和许可协议。
5. **最终验收**：相关数值/生命周期关口通过后，用无重型诊断配置验证输入到可交付回答的时延、失败率和持续资源余量；长诊断链不再在每组性能样本前重跑。

本轮首要成功标准变为：**普通PL R0/hit真实跑完，资源满足原门槛，状态/输出核验通过，正常关闭与独立释放成立。** 然后才用该普通路径的数据修订时延预期。此前“6～10秒首token、11～17秒短回答”仍是有条件的推算，不能作为已具备可实现性证据的结果或承诺。
