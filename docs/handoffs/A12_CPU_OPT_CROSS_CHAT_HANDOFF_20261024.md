## 3. 本会话形成的关键判断

### 3.1 当前模型流程

应用选择本轮允许的事实并组装非思考提示词 → 分词 → R0清空上轮递归/卷积/KV状态 → 本轮输入按T≤8分块 → 每块走完24层 → 最后输入位置计算输出头 → CPU贪心选首token → 发出token事件 → 后续逐tokendecode → EOS/清空/最终结果 → 应用内容检查。

- 模型是Qwen3.5-0.8B，隐藏维1024、MLP维3584，18线性注意力＋6完整注意力；词表248320。
- CPU组织全图并执行注意力、状态、归一化、激活、残差等；PL承担每层gate/up/down三个MLP线性投影。
- gate/up共享输入量化已存在；down对激活/门控后的新输入独立量化。72权重每窗口一次加载，不是每token重新上传。
- R0每轮重算**本轮实际提示词**，不等于重载权重/重启模型，也不代表一定发送全部聊天历史。请求内部状态继续用于后续分块和decode。
- 自然样本107输入token＝13×T8＋T3；prefill真实PL调用14×24×3＝1008次。
- prefill完成时的最后logits直接选首token，不需先把首token再跑24层；把它送回模型是为了预测第二个token。
- “首token事件”不同于完整答案通过应用检查，更不同于语音播放开始。当前A12板测预先提供token编号，不包含应用模板与现场分词完整耗时。

### 3.2 “14.26秒”名称不准确，不可继续误读

`other_norm_activation_residual` 是默认分类桶，**不是纯归一化/激活/残差耗时**。实际分类见 `request_profile.cpp`；未按名字识别的非MLP矩阵投影、拼接、部分复制、小算子和既有节点屏障等待会进入。

PL natural_profile该桶14.264297秒、29310个计时节点组、1106个融合省略节点；同窗口CPU为14.385696秒，数量相同。现有聚合不能拆出每种算子或屏障分别几秒，不能从节点数量反推时间。

CPU循环计时从thread0当前节点开始至既有屏障后；融合组归首节点，一次计时。VIEW/RESHAPE等空操作跳过，不能以其数量推定大量执行耗时；图准备另计。

非MLP稳定投影hook逐token使用原SIMD GEMV，再逐步CONCAT；T8每个投影8次GEMV＋7次拼接。按代码/当前107-token分块静态推算，该投影路径约12198次GEMV、10602次CONCAT，**不是新增实测计数，也不全在14.26秒桶中**。这是任务03的主要候选。

不能直接换回批量GEMM：A05已保存批量调度/浮点舍入改变A8码的失败；仅短文本相同不足以证明数值/状态不变。已有RMSNorm+MUL融合、稳定FlashAttention归约策略都必须保留。
