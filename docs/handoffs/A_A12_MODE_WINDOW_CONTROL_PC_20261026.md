# A12 P1-4 窗口模式与严格回退：无板 PC 验证（2026-10-26）

新增实际 PC 协调器、只读授权页观察器和独立历史审计。当前源码四窗口流程通过，累计 23 项新检查及 11 个真实 CPU 模型窗口审计完成。目标仍 active；没有上板、SSH、恢复、部署、推送或修改 B/HLS/公共数学/ABI。原普通资源探测包保持原 SHA，仍是恢复并确认安全释放后的第一板测基线。

## 实际边界

`ModeCoordinator` 只接受 `PC_STRICT_CONTROL`（cap1）和 `PC_BATCH_CANDIDATE`（cap72），默认严格。候选要求明确的布尔型可信 worker 配置和逐窗口制品/源码 capsule 核对。`RESOURCE_PROBE`、`STRICT_NUMERIC`、`PERF_ACCEPTANCE`、`SERVICE` 与 BOARD 名称都不能在此入口启用；它不是板端模式注册器，也没有把 cap1 误称为完整数值验收。

每个窗口使用原真实 PC 原生程序、CPU 数学库和已冻结微批适配库，内部仍执行原 R0/warm/hit。mode child 只增加独立控制通道、生命周期遥测和关闭前收口，不改模型/权重/数学或原逐投影/微批算法。父进程在子进程仍活着时取得 pidfd，并通过 SCM_RIGHTS 取得授权页引用；收到的 RW 描述符立即替换为独立 RO 描述符并关闭 RW 副本。观察器以真实原子 load 读状态，导出接口没有 writer API。只读引用在 writer 关闭后仍可观察已撤销状态。

切换仅在实际观察到 manager/native pidfd 已终止、页已撤销、无活动/未知授权并且原生日志/回执独立审计通过后进行。代码更新或 capsule 改变使边界核对失效。日志或文件本身不被当成当前进程活性证明；对旧文件的事后审计始终 `release_allowed=false/replay_allowed=false`。

故障窗口进入 `FAILED_DRAINED_PC`，保留失败与未知在途位，不把旧页清零或给已扣额度退款。仅在原活进程句柄确认终止、旧页仍撤销时，允许**为显式指定的新验证窗口**选择严格模式；该方法不自动启动计算。失败/旧窗口 ID 拒绝复用，故障候选在会话及正常重启后仍锁定，不自动重新启用。实际板卡有 DMA，不能用这个 PC 进程退出判据代替 BO/驱动/设备释放门禁。

## 持久化与取消

本地协调锁跨 mode child 继承，父协调器退出后仍由存活子进程持有。它仅是同一 PC 测试命名空间内的锁，不是三台电脑的全局板卡租约。

授权前先持久化 `DIRTY.json`、会话及 WINDOW_BEGIN。模式日志限128条/512KiB，记录范围与原件摘要，非逐投影登记。每次边界读取核对小型日志及 marker，不读取长前缀或全量诊断。正常 SESSION_CLOSE 及 fsync 成功后才清理临时 live marker；历史失败日志不删除。若完整 CLOSE 字节已写但 fsync 失败，marker 仍保留，重启拒绝，不能靠“字节齐全”追认持久化成功。完整哈希链也必须通过独立事件语义审计，不能用尾行 SESSION_CLOSE 掩盖活动窗口。

取消先发控制消息，再处理日志或等待协调器锁。mode child 独立线程执行原子撤销与隔离，主线程等待模型时仍可响应；协调器 EOF 同样触发撤销。控制线程停止后才关闭/解除映射授权页，原有 health/worker/owner FD 关闭顺序继续保持。超时只请求取消并保留句柄，不判定进程已停，不强杀、重放、移交或复位。

真实模型窗口共11个（7正常、4失败），分为：

| 场景 | 实际行为 |
| --- | --- |
| transitions-01，4窗口 | 严格→微批→微批故障→显式新窗口严格；活动期切换、旧 ID 重放及重新启用候选均拒绝 |
| cancel-01，2窗口 | 活动期间发取消，0核验答案交付；确认进程终止/页撤销后，为新窗口严格执行 |

capsule-v2 的早期模型/取消/退出实验和对应源快照保留；capsule-v3 是修复后的当前入口。二者变化是遥测拒绝分支释放新 pidfd，不能把所有旧实验都说成当前源码运行。当前4窗口单独列明；取消和 EOF 接收器源码未变。

这里的输入 ID 是显式独立 PC 验证窗口 ID，内部仍重复固定 R0/warm/hit 合成语料。它证明窗口不自动重启、不复用失败窗口 ID/旧授权、不补写失败结果，**不代表真实用户请求去重或 SERVICE 路由已实现**。生产应用接线仍未完成。

## 性能与 PL 接线边界

本轮验证模式安全，不新增板端性能承诺。协调器按三请求验收窗口收口，模式边界重建 worker、加载权重并重新 warm；这些是切换/准备成本，不能拿内层单请求约4s/2s的 PC 数值代替用户端到端时间或 Board预测。正常服务常驻、交互式请求路由仍需接线。没有新增长前缀、原始状态/全位置 logits 文件，也没有重读旧519.70MiB诊断原件。
