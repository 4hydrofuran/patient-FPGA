## 2. 实际解决的阻碍与保留失败

1. **warm编码缺口**：旧v2回放按ID取结果，没有发现warm被同样删除tokens。真实接入将应用请求与warm编码区分；warm保留完整70个token，应用保留生产prompt输入。前轮源码不改写，新增负例验证删掉warm tokens会拒绝。
2. **复用job后的旧可消费标记**：初版适配库正确拒绝旧job、未发新许可、未改变输出，但仍保留前次 `pc_output_consumable=true`。ABI测试实际失败，见 `abi-tests-01/BAD_JOB.json`。修复为每次run入口在锁内先清除标记，独立构建v2并复测通过；原库、源码和失败保留。
3. **错误原因遮蔽**：健康拒绝会被旧时钟助手归成 `policy response is not a model baseline`。新入口保留旧异常链，同时报告真实健康/持久化拒绝；未把健康失败改成策略回答，也未重写历史CMA失败原因。
4. **测试框架启动错误**：首版接入测试用 `run` 保存数据，遮蔽unittest入口，0项实际运行。改名后8项通过；启动错误与当时源码保存在 `integration-tests-01/`，不补记PASS。

最终适配库SHA：`e71ef0cb886f591b0138040aa52460cf1d29e2836acf719ebef43c9d7803f675`。构建v2仍有原样复制的旧prefix_cache.hpp缩进告警，记录保留；不宣称所有编译告警清零。

## 4. 三种真实模型调用链故障

在实际日志FD注入错误，使用真实原生模型进程，不改磁盘容量或制造真实硬件损坏：

| 注入点 | 真实CPU完成 | 已交付核验答案 | 实际处理 |
| --- | ---: | ---: | --- |
| BEGIN fsync | 0 | 0 | 输入未发送，不开始模型请求 |
| END fsync | 1440 | 0 | 原生已产生正确完整答案并清理状态，但日志失败仍拒绝交付 |
| 首次提交健康拒绝 | 0 | 0 | CPU API没有转发执行，晚到原生ERROR不交付；原始健康原因保持 |

三种故障均保持失败，不自动重放/退款许可。已知x86 PC进程以EOF合作退出，实际exit2；不记作正常关闭，不发强杀信号，不声称释放任何板端平台。健康失败后，原生晚到ERROR只作离线取证，不能替换运行时已锁存的失败。独立审计均拒绝完整收口，并始终 `replay_allowed=false/release_allowed=false`。

相关原件：`run-fail-begin-v2-01/`、`run-fail-end-v2-01/`、`run-fail-health-v2-01/`。正常/失败私有原件仍在既有WSL；小型副本归入 `native-transcripts/`。无全局drop_caches、无删除旧证据、无原始状态/全位置logits转储，未读取旧519.70MiB诊断链。真实前缀状态约22058035字节仍按原语义驻留，不能据此推断板端CMA可用或长期无泄漏。
