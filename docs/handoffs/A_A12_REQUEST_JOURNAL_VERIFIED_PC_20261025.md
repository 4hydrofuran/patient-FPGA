# A12 请求级日志：结果核验与故障收口的无板候选（2026-10-25）

本轮将上一轮的请求级日志原型推进为**有结果核验的PC控制候选**，并复核短提示词失败。最终20项测试通过；未运行新模型或PL，未形成可上板执行入口。原普通资源探测包继续冻结，板端时延/CMA收益为null。

## 1. 修复的实际缺口

旧原型的append边界测试没有覆盖持续底层日志故障。此次在私有PC文件和真实子进程/socket上注入fsync错误：旧许可线程进入异常处理后，写故障日志再次失败，线程退出，等待回复的子进程没有收到EOF。该缺口已复现，记录在 `pc-tests-05/V1_FAULT_REPRODUCTION.json`；旧源码和历史测试保留，不追认已覆盖。

新 [request_journal_verified.py](C:/Patientqwen/platform/qwen35/a12/request_journal_verified.py) 在原许可循环外增加异常收口：底层写入失败后锁存，禁止重复尝试，并关闭许可socket的回复方向，使等待者收到EOF；故障日志自身失败也执行这一步。读取线程故障同样保留隔离并通知等待端。

**关闭回复方向只阻止新的许可交付，不证明已有提交完成或设备已停止。** 不强杀、不重启、不卸载、不退款提交预算，不清除失败；进程、FD和平台所有权继续按未知状态保留。文件系统持续失效时，不能保证故障记录或关闭回执写成功，也不以此为由释放。

## 2. 请求结束改为读取并核验结果

不再开放调用者直接填写“累计完成数、pending=0、状态已清理”来完成请求的接口。新增控制器只处理原冻结的 `app_R0 → warm_prefix → app_hit` 三请求：

- 重新核对冻结清单SHA，读取小配置及原BO/应用纯函数；不执行原板端管理器，不导入暂停中的CMA读取候选。
- 核对ready、构建号、微批8、72次权重加载、148 BO及140591104字节、8192对齐和低2GiB边界，冻结本次BO/权重清单与缓存身份。
- BEGIN先持久化，绑定实际wire请求、冻结输入、ready和缓存SHA；保留原5000总硬上限及本包3024最坏提交预算，不重用请求ID或已消费许可。
- 结果核对ID/type/status、状态清理、实际R0/hit、新算/复用token、EOS/输出边界、末位置logits和原内容checker，严格对齐原逐投影许可与host-verified完成计数；hit继续与R0原字段比较。BO/权重类型也严格比较，布尔值不冒充整数。
- 结果关口通过后才写END，再写绑定该END/输入/结果/校验摘要的提交回执；回执持久化失败仍隔离，END一行不算成功提交。
- 正常收口必须有router_close许可、正常exit0、许可/读取线程均结束及关闭回执。仅exit0而缺关闭许可会拒绝；已完成的重复close不重新写回执。

原双序号、许可顺序和每次新鲜所有权/健康检查仍委托原冻结循环执行。没有将健康判断缓存，也没有微批/整请求一次授权。板端原有BO同步、meta、输出消费的原生核验代码和公共ABI/B核均未修改。

**本候选只接受明确的PC控制替身。** real设备、ARM、实际CPU native ready及无PC fixture标签均不能作为新控制器的板端入口。测试使用既有CPU输出作为协议回放数据，并模拟许可/完成；内层FPGA形状字段仅用于控制替身的协议测试，不是硬件执行证据。

## 3. 持久化和离线审计

日志使用逐行序号和语义摘要链，最多256条、单条32KiB、总512KiB；逐提交仅保留64条环和累计摘要。三个请求最多三份提交回执及一份关闭回执，每份8KiB上限。未新增长前缀诊断、全位置logits或原始状态文件。这里的上限约束新增日志，不是整个worker内存峰值证明。

[request_journal_audit.py](C:/Patientqwen/platform/qwen35/a12/request_journal_audit.py) 只读私有PC目录，核对清单、序号/语义SHA、冻结请求/预算/身份、权重启动顺序、请求BEGIN/END、提交和关闭回执，以及读取前后文件身份。残缺、乱序、替换、重复JSON字段、越界、链接、缺回执和读后改变均拒绝或判未知；原件不改写。

审计只报告当前字节的结构和一致性，**不能从完整文件推断先前fsync曾成功**，也不是签名或独立设备释放证明。故障测试特意保留一个反例：关闭回执完整写出后fsync报错，运行时close返回false，而当前文件仍可能结构完整。审计在任何结果下均返回 `release_allowed=false`、`replay_allowed=false`，硬件完成数null；不能用格式完整覆盖运行时失败或自动恢复。

现场NTFS/DrvFS目录呈现0777，不能直接通过私有目录门槛。命令行验证只把小型日志fixture复制到现有WSL私有目录，保留原件并核对字节；未放宽权限判断。回放复制脚本为证据目录内的 `cli_prepare.py`。私有副本位于 `/home/member-a/kv260-build/a12-request-journal-v2-cli-20261025`，不含模型/大诊断。
