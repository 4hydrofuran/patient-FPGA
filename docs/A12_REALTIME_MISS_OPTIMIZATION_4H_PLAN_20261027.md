# A12：缓存未命中实时模型路径，4小时无板优化

日期2026-10-27（北京时间）。目标是提交问题后尽快显示完整、原checker通过的回答；本轮必须实时运行目标模型，不能用答案缓存命中代替验收。接续已封存的34-token/2线程实时CPU网页基线和198条目录，不覆盖旧包/证据。

## 已有证据与目标

旧真实浏览器25题完整答案显示中位875.0ms，范围755.0～1630.1ms。真实缺失条目一题从服务接受到发布847.1ms，其中prefill401.9ms、decode378.4ms。它们都是开发机CPU参考结果；新的实板数值仍NOT_TESTED/null。

主要尝试是**事实草稿的实时目标模型贪心验证**：草稿来自本次输入中的原病例事实，不读取已核验答案目录；目标模型实际计算每个候选token及EOS的logits。仅当所有token等于原贪心sampler选择且EOS通过时交付。任何不同都丢弃草稿后缀，清除全部recurrent/conv/KV状态，从原中性前缀重放当前prompt并正常实时生成；不对DeltaNet做未经验证的部分状态截断，不放宽checker，不采纳近似top-k。

可将原prompt尾部与草稿合并为有界因果batch，复用现有physical_ubatch=8，减少串行decode/PL调用轮次。原量化、HLS、公共数学/算子ABI、模型和原采样规则不改。该方法参考[llama.cpp官方投机解码说明](https://github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md)和[Draft & Verify论文](https://arxiv.org/abs/2309.08168)，实际实现以本地固定运行库API为准，不升级运行库或安装新模型。

## M2发现的最小反例及显式修订

`pairs198-v2/proof/pair-039-serial.json`：SYN_CP_01的duration+severity双事实，真实贪心文本已用24个输出token，末尾句号后仍需一次EOS选择，因此原24上限eos=false。该失败不是新草稿引入，不能删掉该组合或降低完整性要求。原198条64上限目录中有3条输出恰为24 token，最大仍24。

新连续候选输出上限改为32；配对控制和优化组同时使用32以比较完整回答，原已封存25题/24上限速度结论不追改。普通R0/warm/hit窗口仍保留原24上限与独立预算。新连续保守逐问预算为 `2 * 72 * (ceil((1024-34)/8) + 32-1) = 22320`，包含完整验证及最坏串行重放；实际消耗另记，不能与预算混淆。

## 继续减少输入与输出token的受控尝试
