## 1. 总体策略与边界

先建立可核算的瓶颈账，再分别优化两条路径，最后组合验证：

- **管理路径**：模型回调 → 提交许可 → 新鲜健康/所有权检查 → 持久记录 → XRT调用及结果检查。
- **计算路径**：非MLP矩阵投影 → 拼接/复制 → 归一化、激活、残差、注意力及混合状态 → 线程同步。

以当前健康优化后的版本为基线，避免重复认领已完成的收益。每个候选先单独评价，组合收益必须重新测量，不能把独立试验的节省秒数直接相加。

本轮主线保持：

1. 模型、tokenizer、提示词模板、权重、非思考模式、公共数学/ABI、PL核与xclbin不变；同模型同工作量比较。
2. R0完整本轮输入重算保留；R1/R2、跨请求前缀缓存、提示词缩短另列可选研究，不混进本计划主收益。
3. 物理T≤8、单在途任务、失败输出不可消费、未知DMA状态隔离、每次提交的新鲜观察与持久许可记录保留；不以减少检查覆盖率、降低阈值或取消fsync提速。
4. 不新增HLS核，不把注意力/归一化迁往PL，不做推测解码、异步多任务流水或公共协议重排。
5. 默认FPGA仍关闭；候选在独立目录/维护窗口选择，不能覆盖历史库、失败包或封存证据。2026.1工具与现有A53 SDK复用，不全局升级依赖、不使用开发机 `-march=native`。

### 2.1 输入处理的互斥分解

下表来自最新PL `natural_profile` 的prefill，单位秒；其中MLP包含管理与检查，不能只理解为硬件数学计算。

| 区间 | 秒 | 处理原则 |
|---|---:|---|
| 提交许可等待 | 19.803 | 最大的已定位CPU管理路径；先细分，再优化等价实现 |
| 非MLP CPU图 | 16.955 | 第二主线；包括真实矩阵计算、小算子、数据移动及同步 |
| 提交至确认完成 | 11.523 | 主机墙时，包含硬件与轮询等待；先辨别CPU等待机制，不当作纯CPU或纯核周期 |
| MLP内同步、检查、参数及复制等后端工作 | 2.653 | 其中输出检查约2.471秒，是明确候选 |
| MLP输入gather、量化、缓存及输出复制 | 0.759 | 优先避免重复处理；gate/up共享量化已存在 |
| MLP桥接与其余运行时工作 | 1.080 | 含完成报告等剩余工作；须继续保持分账 |
| 图准备/调度 | 0.076 | 当前占比很小，不先重写图构建 |
| **prefill合计** | **52.848** | 舍入误差约0.001秒 |

后两项MLP分解口径：0.759为gather/quant/cache/output-copy之和；1.080为bridge_other及线性服务中除许可、提交等待、上述后端分项后的余额。余额不是一个已定位函数，须由步骤01进一步分解。父区间MLP inclusive约35.817秒，不再另加。

首token接收时间为52.867秒；状态清空约0.004秒，prefill后首token选择/摘要约0.009秒，其余请求/事件传递约0.006秒。板测使用预先冻结的token编号，应用模板和现场分词不在这段完整计时中。

### 2.2 不能按名称误读的14.264秒

`other_norm_activation_residual` 是默认分类桶：未命中其他分类的节点都会进入。它不等于纯归一化/激活时间，也不是纯管理开销。其29310个计时节点组、1106个融合省略节点，在CPU/PL两模式相同；CPU对应14.386秒，PL对应14.264秒。

该桶包括未按名称识别的非MLP投影、小算子、部分拼接/复制及既有节点屏障等待。归一化、激活、残差、矩阵乘和等待各占多少秒，现有聚合日志不能确定。VIEW/RESHAPE等空操作被计算循环跳过，不以它们的数量推定计算时间。

[稳定投影实现](../runtime/qwen35_w4a8/sp-hook.cpp)对非MLP投影逐token调用SIMD GEMV，再逐步CONCAT。根据18层线性注意力、6层完整注意力及当前分块静态推算，107-token输入的该投影路径约有12198次GEMV、10602次CONCAT。这是代码推算，不是新增实测计数；这些节点不全部属于上述默认桶。

- [ ] 输出头prefill仅约0.163秒，不优先改词表、裁剪候选或更改采样。decode输出头可单列热点，但不混为首token输入处理收益。

通过：既有独立整数/FP32参考、实际MLP/非MLPshape与相关模型位置通过；CPU-only与PL模式分别报告，不以CPU被优化后的新对照掩盖PL的真实表现。

### 06｜按证据融合小算子

- [ ] 只处理累计耗时足够大的链条，候选包括残差加法接归一化、门控激活接乘法、相邻尺度调整；已有RMSNorm+MUL融合不重复实现。
- [ ] 区分减少中间内存读写与减少屏障的效果；检查stride、广播、别名、多个消费者及诊断可观察性。
- [ ] 优先保持原FP32运算顺序和每个中间舍入；数学等价不自动代表量化输入逐位一致。
- [ ] 对A8阈值附近输入、极小/极大值、零向量与跨分块状态验证；失败保存首个不同节点和最小反例。

通过：操作级与同板模型数值/状态通过，融合前后CPU墙时确实改善；不能把算子数减少直接当作性能通过。

### 07｜评估线程粒度及等待方式

- [ ] 当前固定对照为GGML两线程、MLP两线程；在独立启动配置中比较1/2线程及必要的受限组合，分别评价prefill与decode。
- [ ] 根据01热点区分单任务小节点、多线程矩阵、单线程MLP回调和现有OpenMP屏障；不删除数据依赖要求的同步。
- [ ] 只在证据支持时评估小节点连续执行、融合组任务粒度、线程亲和性或OpenMP等待设置；管理/许可线程、系统服务和CPU计算的竞争一并记录。
- [ ] 对提交至完成的11.523秒，仅评估主机轮询/等待消耗及其对其他CPU工作的影响；没有设备周期计数时不声称改变了硬件算速，不以忙轮询换未记录的CPU占用。
- [ ] 选择在进程启动/维护窗口生效，不运行中动态切换公共后端；不对全系统长期修改调度器或电源策略。

通过：没有死锁/取消延迟/温度和资源风险，首token改善且完整回答与decode没有不可接受退步。单线程不预设更快，降低CPU占用也不自动等于降低墙时。

## 4. 正确性门槛与停止规则

1. 图调度/复制/管理等保持语义的改动，优先要求同板旧/新投影、logits和递归/卷积/KV状态逐位一致；同时保留公共算子的既有独立参考和容差，不放宽门槛。
2. 数值差异即使没有改变几个输出token，也必须定位首个分歧；不得用短文本相同替代完整数值或状态检查。现有跨ISA整图限制保留，PC PASS不能替代BOARD恢复与同板验证。
3. 既有A05批量归约改变A8码、零输出崩溃，以及A12错身份/旧Y/未消费/取消迟到结果等反例，按改动相关性复用；不删除失败样本、不用新输入覆盖旧失败。
4. 每个候选先完成可定位修复；连续10分钟仍无法定位的重大问题，保存现场与最小复现，停止该候选并报告。合法的长输入运行耗时不等于“故障10分钟”；预算、超时和停止边界在运行前冻结。
5. 任何数值/内存所有权错误、未知在途状态、许可记录失败、新内核异常或恢复失败立即停新提交，执行既有隔离/收口流程；不能为了拿到速度结果继续扩大范围。

## 5. 收益解释与可选项
