# KV260 / Qwen3.5 A12：快速响应与核验答案缓存无板交付总结

交付日期：2026-10-27（北京时间）；交付版本：v1。适用模型为 `Qwen/Qwen3.5-0.8B`，文本、非思考模式。本总结覆盖本轮短提示词工程 N0～N6，以及用户授权后的核验模型答案缓存工程 C0～C5。

## 这份工程解决什么问题

目标是用户提交一句问题后，尽快看到完整、事实核验通过、可参与原评分的回答。当前推荐候选在连续网页中复用此前由真实模型生成并核验的答案；每次提交仍重新路由、检查病例事实、核验答案、生成本次交付回执和评分。页面明确显示“已核验模型答案·缓存”。

用户已明确授权：“允许已核验模型答案复用，保留来源标记”。缓存命中本轮不再运行模型；缺少条目或身份不一致时继续原实时模型路径。它适用于现有三个固定合成病例，不能据此宣称任意新病例或任意问题均有同样速度。

## 实际改善多少

以下是同一开发机、真实 Edge 浏览器、真实 HTTP/SSE、25个相同病例/问题/输出的逐题对照。计时起点为浏览器提交，终点为完整核验答案更新 DOM 后两次 animation frame；包含服务处理与网页交付，不含打字、语音识别或服务启动。

| 指标 | 优化前：原v2实时CPU模型网页 | 优化后：核验答案缓存命中 |
| --- | ---: | ---: |
| 最快 | 755.0毫秒 | 29.5毫秒 |
| 中位 | 875.0毫秒 | **42.3毫秒** |
| 最慢 | 1630.1毫秒 | 69.8毫秒 |
| 缓存组1秒内显示 | — | **25/25** |
| 本轮实际模型生成次数 | 25 | **0** |

两组中位数相差832.7毫秒，等待时间降低约95.2%；逐题配对差值的中位为835.8毫秒。这是将已核验答案的生成成本移到提问之前所取得的效果，不表示模型本身推理快了95.2%。25题样本不构成长时间稳定性或总体分位数结论。

此前实板27.854秒等历史结果属于不同路径和测量环境，不能与这里42.3毫秒相减计算实板加速比。本次没有连接板卡，新的板端响应时间仍未测试。

逐题数据与原始回执在 `evidence/model_pl_A/20261027-verified-answer-cache-v1/AB_FINAL.csv`、`AB_FINAL.json`、`live-browser01/`、`cache-browser03/`。完整报告为同目录 `REPORT.md`。

缓存目录键取决于原planner选中的事实；不同问法可以命中相同事实键。超过当前planner能力的请求继续原澄清/策略流程。模型、病例或checker身份改变时旧条目不应继续命中，需重新生成并核验。

缓存来源为 `MODEL_CACHE`：本轮 `model_called=false`、`actual_backend=null`、当前PL提交为0。`cache_provenance`独立保存原CPU_REFERENCE生成来源、模型与文本摘要、原请求及EOS证据。原CPU答案不会被标成本轮FPGA_REAL。

连续网页 `continuous/` 启用复用；普通 `ordinary/` 的R0/warm/hit窗口仍运行实时模型。板端未命中保留原NativePL/FPGA_REQUIRED路径，不自动切换CPU。

## 怎么使用及后续还需什么

1. 下载推荐总交付包，按仓库 `SHA256SUMS.txt` 核对摘要，解压后先看 `README_zh-CN.md`。
2. 解压Deployment包，阅读其 `hybrid34-threads2/START_HERE.md`；按其中PC package检查先验证离线依赖与目录。
3. 源码在新的复核目录展开，保留现有工程和旧证据；按Stage01→Stage02顺序接续，勿直接覆盖有未保存修改的工作区。
4. 当前部署候选为UNBOUND。另行授权实板后，才按包内入口创建新窗口，验证少量缓存可见问题、一次真实PL未命中及原Owner恢复/独立释放。结束问诊只冻结评分；停止服务需按包内停止流程等待完成回执。
5. 需要回退时，先正常停止并释放当前窗口，再从独立的Short34T2或Legacy70T2包开新窗口，不复用已经消费的授权窗口。
