# A12：核验模型答案复用，约10小时无板执行方案

日期：2026-10-27（Asia/Shanghai）。用户已明确允许“已核验模型答案复用，保留来源标记”，并要求本方案生成后持续执行到无板工作完成。本方案接续 `release/a12_fast_response_20261027_v2/`，不覆盖它及旧证据。

## 目标与实施选择

主要指标保持为：提交当前问题到**完整、事实核验通过的答案完成浏览器绘制**。命中答案缓存时，PC实测目标为每条不超过1秒，争取中位不超过0.3秒；未来板端目标为1秒左右，仍须板测。它们是验收目标，不是已有成绩。缓存未命中仍走原34-token真实模型路径，不承诺未命中也达到1秒。

这次把已验证模型答案的生成移到提问之前。每次问题仍经过原 planner、原病例事实、原 checker、请求/场次归属、发布回执和原评分。缓存是完整模型原文及其来源，不是把 forms/fallback 字符串伪装成模型生成。

```text
离线：固定模型与病例 → 真实贪心生成 → 原checker + EOS → 带来源的答案目录
启动：原Owner/同一worker/34-token warm + 加载固定答案目录 → ready
每问：原输入 → 原planner/评分证据 → 精确事实键
  命中：原checker再核验 → 新请求发布回执 MODEL_CACHE → SSE → 完整答案绘制
  未命中：原NativePL真实生成/检查/EOS → 原MODEL发布
结束：冻结当前评分；停止服务仍走原Owner和原恢复链
```

不训练、不改量化/HLS/xclbin/公共算子ABI、不换运行库、不引入第二个resident服务、不显示未核验生成片段。投机解码虽可批量验证草稿，[原论文](https://arxiv.org/abs/2211.17192)和[llama.cpp官方说明](https://github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md)已有方法，但本项目还要处理混合状态恢复，10小时内优先完成用户已允许的答案复用。

## 已确认的可行性与范围

原 planner 在三个固定合成病例中最多选择两个事实，超过两个转原澄清策略。当前每例11个事实，因此单事实33键、双事实165键，总共198键。已实际枚举，见 `evidence/model_pl_A/20261027-answer-cache-design-v1/FEASIBILITY.json`；185个不同的原核验表达，最大25个字符。该枚举没有执行新模型生成，不能当成缓存质量通过。

缓存键包含病例ID/版本/完整SHA、所选事实的值/单位/时间/肯否/未知、必需事实顺序、句数限制和固定模型资产/量化/prompt/template/checker版本。原始问法不作为答案键；它仍完整保留用于路由、追问、请求幂等和评分。同一病例同一事实的不同问法可以命中；不同病例或事实版本不能串用。

目录生成使用现有真实CPU Qwen3.5-0.8B、非思考、贪心、无teacher forcing。离线最多64输出token以确保双事实完整EOS，不修改在线未命中路径的24输出/1024上下文/10584预留。每条只有原始生成文本、原checker及EOS通过后才可入库。失败不填模板，不删键，不伪造覆盖率；必要时只对失败键定位并采用同一checker已允许的更短完整表达，再实际生成与复验，记录独立生成策略。

## 来源与交付语义

新增明确来源 `MODEL_CACHE`。本轮字段必须为 `llm_calls=0`、`actual_backend=null`、本轮PL提交为0；原生成后端、模型/二进制/库摘要、原请求ID、原EOS与文本SHA放入 `cache_provenance`。CPU生成的条目明确标记原后端 CPU_REFERENCE，绝不标成本轮FPGA_REAL。

网页交付回执显式增加v2缓存来源字段，保留旧v1模型/模板回执读取；这是网页内部协议修订，不改公共算子ABI。界面每条缓存答案显示“已核验模型答案·缓存”，服务就绪提示不声称每条都发生PL计算。仍保留合成教学病例/待教师审核标记。

缓存目录为启动期校验并载入的有界只读数据，目标热目录不超过2MiB、缓存附加内存不超过8MiB，实际测量后报告。不保存第二份模型状态、不缓存动态健康/占用/在途结果，不延长Owner时限，不重置许可额度。目录不包含计算授权。未命中在BOARD继续原fpga_required路径，不自动改CPU；预算不足仍在发送前拒绝。

## 验收与性能报告要求

1. 198键逐条必须有真实模型生成、非teacher-forced、EOS、原checker通过及文本摘要。目标198/198；任何缺件/失败都保留，不将表达枚举算生成。25个原固定输入必须全部可命中。
2. 7策略输入零模型；不同问法/同场追问重新路由与评分；同场两问20分；新病例、重复提交、旧epoch、归档读取正常。
3. 变更病例事实、模型/prompt/checker身份或缺失条目会拒绝旧命中；合法未命中实际执行一次模型，BOARD不静默CPU回退。
4. 缓存命中无native send、无新prefill/decode、无本轮PL计数；所有MODEL_CACHE有可追溯原生成结果。网页不能把原后端标成本轮后端。
5. **真正的前后对照**：同一机器、同一问题/病例/输出、相同浏览器与计时口径。A为v2真实CPU模型网页，B为新缓存网页。两边都使用真实HTTP/SSE和实际DOM绘制，不能用伪模型/模拟SSE的毫秒数报响应速度。
6. 报每题A/B秒数与减少秒数、25对的min/median/max及逐题差值中位数、1秒达标n/25。缓存命中/未命中/策略分别统计，缺绘制回执算未验证。首次离线建库和服务ready耗时单列，不能藏进提问前而不报告。
7. 缓存热目录字节、附加内存、构建生成总次数/耗时均实测。3线程对缓存命中无主要收益，不列为必做；可选短输出调优不阻断主线。
8. 正常stop用原协议接线证明；真实硬件恢复/释放仍为BOARD NOT_TESTED。所有BOARD时延/功耗/CMA/计数为null。

## 阻碍处理规则
